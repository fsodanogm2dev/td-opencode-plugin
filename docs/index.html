In plain words

This page explains what the plugin does and how you can check each part yourself. The first part needs no technical knowledge. Each section then shows the commands and the code behind it.

Terms

OpenCode
an AI coding assistant that runs on your computer. OpenChamber is a desktop app that runs OpenCode.
FueliX
the TELUS service that gives access to AI models from OpenAI, Anthropic, Google, and others, with one account and one key.
Model
one specific AI, for example GPT-6.1 Terra or Claude Haiku 5.5.
Provider
a group of models that use the same type of connection. The plugin adds three FueliX providers to OpenCode.
Token
the unit that models use to count text. A token is a short piece of a word. Prices are per 1 million tokens.
API key
the secret that proves that a request comes from your FueliX account.
Plugin
an add-on that gives OpenCode new features.

What the plugin does for you

1

Every FueliX model, with its price

OpenCode shows all FueliX models with their correct price and limits. When FueliX adds a model, it appears in OpenCode within an hour. You do not keep model lists in your settings file.

2

One key, kept private

You store your FueliX key once. The plugin adds it to every request to FueliX. The key does not appear in the information that OpenCode shares with other programs on your computer.

3

Cheaper session titles

OpenCode names each conversation with a short title. The plugin makes OpenCode write that title with a low-cost model instead of the model you chat with.

How it works

OpenCode sends each request through the plugin to FueliX. The plugin adds your key, and FueliX sends the request on to the service that runs the model.

The model list

What it does

When OpenCode starts, the plugin asks FueliX for its list of models. It asks again every 60 minutes, so a new FueliX model appears without any action from you.

For each model, the plugin needs the price, the limits, and the kinds of input that the model accepts: text, images, or PDF files. The limits are how much text the model can read and write in one request. The plugin takes this data from a file in this repository, data/fuelix-models.json. The file is built from the FueliX inventory of models and prices.

If a model is not in that file, the plugin copies the data from OpenCode's own model list when it finds the same model there. Otherwise the model gets default limits (200,000 tokens of context, 32,000 tokens of output) and no price, and the plugin logs it.

If FueliX suddenly returns a much shorter list, the plugin keeps the previous list. "Much shorter" means that more than 30% of the models are missing, or that all models of one provider are missing. A problem at FueliX then does not remove models from OpenCode.

Your FueliX key

What it does

You store your FueliX key once. The plugin looks in three places, in this order, and uses the first key that it finds:

  1. The macOS Keychain, item fuelix-api-key. The Keychain stores the key encrypted.
  2. The OpenCode credential store. You add a key there with /connect in OpenCode.
  3. The environment variable FUELIX_API_KEY.

The plugin adds the key to every request that OpenCode sends to FueliX. The key does not go into the provider settings that OpenCode shares with other programs on your computer through its local API.

Three more protections:

  • When an AI agent runs a shell command in OpenCode, the plugin removes FUELIX_API_KEY from the environment of that command. The agent then cannot print the key by accident.
  • The plugin sends the key only to https://api.fuelix.ai. To use another address, you must set TD_OPENCODE_ALLOW_CUSTOM_FUELIX_URL=1, and the address must use https.
  • If your OpenCode settings file still contains old FueliX provider blocks with a key, the plugin logs one warning. The warning names the provider and the field, never the key.

Check it yourself

  1. Check that the key does not appear in the data that OpenCode shares. The commands read your key from the Keychain and print only how many times they found it. Both results must be 0:

    Command

    K="$(security find-generic-password -s fuelix-api-key -w)"
opencode api get /api/provider | grep -c -F "$K"
opencode api get /api/model | grep -c -F "$K"
unset K
    Expected result
    0
0

  2. Check that no FueliX provider has a key field. Every value must be false:

    Command

    opencode api get /api/provider | jq -c '[.data[] | select(.id | startswith("fuelix")) | {id, settingsApiKey: (.settings.apiKey != null), authHeader: ((.headers // {}) | keys | map(ascii_downcase) | any(. == "authorization" or . == "x-api-key"))}]'
    Expected result
    [{"id":"fuelix-openai","settingsApiKey":false,"authHeader":false},{"id":"fuelix-anthropic","settingsApiKey":false,"authHeader":false},{"id":"fuelix","settingsApiKey":false,"authHeader":false}]

  3. In an OpenCode session, ask the agent to run env | grep -c '^FUELIX_API_KEY='. The result must be 0.

  4. Send a message with any FueliX model. You get an answer. This means that FueliX accepted the key.

Session titles

What it does

OpenCode gives each conversation a short title. To write it, OpenCode sends one extra request to a model. It looks for a small model of the same provider through a label called family. Without that label, it writes the title with the model you chat with, which can cost much more. For example: Claude Opus instead of Claude Haiku.

The plugin sets the family label on one low-cost model per provider:

Session providerTitle model
fuelix-openaigpt-6-luna
fuelix-anthropicclaude-haiku-5-5
fuelixgemini-3.1-flash-lite

If that model fails, OpenCode writes the title with the model you chat with. To choose another title model, set agents.title.model in your OpenCode settings.

  participant F as FueliX

  Note over O: Reads the title mark<br>of fuelix-anthropic
  O->>F: Title request to claude-haiku-5-5
  alt Title model answers
    F-->>O: Title
  else Title model fails
    O->>F: Retry with session model claude-opus
    F-->>O: Title
  end
  O-->>S: Session title

Install

  1. Add the plugin

    Add this line to ~/.config/opencode/opencode.json, then remove the old FueliX provider blocks from that file:

    { "plugins": [{ "package": "github:fsodanogm2dev/td-opencode-plugin#v0.2.0", "options": {} }] }

  2. Let git read the repository

    OpenCode installs the plugin with git, so git must be able to read the repository. Use an SSH key or run gh auth setup-git.

  3. Store your key once

    This command asks for the key and stores it in the macOS Keychain:

    security add-generic-password -U -s fuelix-api-key -a "$USER" -w

  4. Check the install

    This command shows the plugin line:

    opencode plugin list
    Expected result
    td-opencode-plugin  b4de498  github:fsodanogm2dev/td-opencode-plugin#v0.2.0
  • OpenCode loads plugins in the background. If a command shows nothing the first time, run it again.
  • The commands on this page use jq. If jq is missing, install it with brew install jq.
  • Full steps: README.md and CHANGELOG.md.

Limitations

Requests through /api/generate

Some tools and plugins use an OpenCode feature called /api/generate for short helper texts. OpenCode does not let plugins add the key to those requests, so some of them fail with error 401. Normal conversations are not affected.

README, section FueliX key

Prompt cache on Claude Haiku 4.5

A model can reuse the earlier part of a conversation at a lower price. This is the prompt cache. On fuelix-anthropic/claude-haiku-4-5, a new message does not reuse it, so each new message costs more than it should. FueliX runs this model on a Google Vertex AI endpoint that reuses the cache only for identical requests. The plugin cannot change this.
