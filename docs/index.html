What the plugin does

The plugin runs inside OpenCode and connects it to the FueliX gateway. It has three features.

FueliX catalog

The plugin registers three providers. It reads the model list from GET https://api.fuelix.ai/v1/models at startup and every 60 minutes.

ProviderAPIEndpoint
fuelix-openaiOpenAI ResponsesPOST /v1/responses
fuelix-anthropicAnthropic MessagesPOST /v1/messages
fuelixChat CompletionsPOST /chat/completions

Price, limits, and modalities come from data/fuelix-models.json. The file is generated from fuelix/LLM-Inventory. The plugin picks the data for each model as follows.

One FueliX key, kept out of API responses

The plugin finds the key in this order. The first match wins.

flowchart TB
  subgraph order["Key sources, checked in order"]
    direction LR
    A["1. macOS Keychain item<br>fuelix-api-key"] -- not found --> B["2. OpenCode credential store<br>(/connect → FuelIX)"]
    B -- not found --> C["3. FUELIX_API_KEY<br>environment variable"]
  end
  order -- first match wins --> H["session.hook http.request<br>sets the Authorization: Bearer header<br>on each FueliX request"]
  class H good
  • FueliX rejects the x-api-key header that the Anthropic package sends. The hook moves that value into the Authorization header.
  • The key never goes into provider settings or headers. GET /api/model returns those to every local client.
  • The plugin also removes FUELIX_API_KEY from agent shell environments.

Low-cost session titles

OpenCode writes each session title with one extra model request. The plugin marks one low-cost model per provider. OpenCode sends the title request to the marked model of the session's provider.

ProviderTitle model
fuelix-openaigpt-6-luna
fuelix-anthropicclaude-haiku-5-5
fuelixgemini-3.1-flash-lite

  end

To change the choice, set agents.title.model in the OpenCode configuration.

Safety checks

The plugin runs these checks without user action.

  • A custom fuelix.baseURL needs TD_OPENCODE_ALLOW_CUSTOM_FUELIX_URL=1 and https.
  • The plugin logs one warning when old FueliX provider blocks in the configuration still expose a key.
  • Discovery rejects a model list that drops more than 30% of the IDs or empties a provider.

Known limitations

POST /api/generate

OpenCode runs no plugin request hooks for POST /api/generate. Those requests carry only the native credential, so some fail with HTTP 401.

Session traffic is not affected.

fuelix-anthropic/claude-haiku-4-5

On this model, a new user turn writes a new prompt cache entry instead of reading the previous one.

FueliX serves the model from the Vertex AI global endpoint. The plugin cannot change this.

Install and check

  1. Add the plugin

    Add this to ~/.config/opencode/opencode.json. Then remove the FueliX provider blocks from that file.

    { "plugins": [{ "package": "github:fsodanogm2dev/td-opencode-plugin#v0.2.0", "options": {} }] }

  2. Let git read the repository

    OpenCode installs the plugin with git. Git must be able to read the repository. Use an SSH key or run gh auth setup-git.

  3. Check the install

    opencode plugin list shows this line.

    td-opencode-plugin  b4de498  github:fsodanogm2dev/td-opencode-plugin#v0.2.0

  4. Set the key once

    For example, in the macOS Keychain.

    security add-generic-password -U -s fuelix-api-key -a "$USER" -w

Full steps: README.md and CHANGELOG.md.
